# Client Chaos Challenge — DevX 2.0

> **Building a focused MVP for Lala Tech LLC by understanding the problem first, then solving the highest-impact workflow.**

## 📌 About the Challenge

Lala Tech LLC currently manages day-to-day operations using a combination of spreadsheets, chat applications, email, manual processes, and disconnected tools.

This has created several operational problems:

* Information gets lost across different platforms
* Tasks can be forgotten or overlooked
* Limited visibility into ongoing work
* Repetitive manual processes
* Difficulty tracking progress
* Time spent on work that could potentially be automated

The objective of this challenge is **not to build an unnecessarily large application**, but to identify one important operational problem and build a practical MVP that meaningfully improves the workflow.

---

## 🎯 Challenge Objective

The development process is focused on four key questions:

1. **What is actually going wrong?**
2. **Which problem has the highest impact?**
3. **What is the simplest practical solution?**
4. **How can we measure the improvement?**

The MVP will prioritize:

> **Impact > Features**

and

> **Working Software > Excessive Documentation**

---

## 🔍 Problem Discovery Approach

Before finalizing the product, the existing workflow is being analyzed to identify:

* Where information is currently stored
* How employees communicate and transfer information
* Where information is duplicated or lost
* Which tasks require repetitive manual work
* Where delays occur
* Where employees lack visibility
* Which process can realistically benefit from automation

Client feedback and additional requests received during the challenge will be incorporated into the product direction.

---

## 💡 MVP Strategy

Rather than attempting to replace every existing tool used by the client, the MVP will focus on **one high-impact workflow**.

The intended approach is:

```text
Understand the Workflow
        ↓
Identify the Bottleneck
        ↓
Validate the Problem
        ↓
Design the MVP
        ↓
Build the Core Workflow
        ↓
Test With Realistic Scenarios
        ↓
Measure the Impact
        ↓
Iterate Based on Client Feedback
```

## 🧠 Product Principles

The project follows a few simple principles:

### 1. Solve the problem, not the brief

The initial brief describes symptoms of the problem. The actual solution will be based on what is discovered through client communication and workflow analysis.

### 2. Keep the MVP focused

A small, reliable solution that solves one important problem is preferable to a large application with many incomplete features.

### 3. Minimize unnecessary manual work

Where appropriate, repetitive actions will be streamlined or automated.

### 4. Make information easier to track

The solution should improve visibility into tasks, progress, ownership, and important operational information.

### 5. Build for change

Since requirements may change during the challenge, the implementation will remain flexible enough to accommodate validated client feedback.
